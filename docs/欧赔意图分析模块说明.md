# 欧赔意图分析模块完整说明

## 一、模块概述

### 1.1 核心功能
这是一个**完全自动化的欧赔分析系统**，基于"骨架参照系 + 初赔 + 即时赔"的输入，自动计算特征值，通过规则引擎匹配模式，最终输出：
- **单项推荐**（H/D/A中的一个）
- **排除最不可能的选项**（可选模式）
- **置信度评分**
- **可解释的分析原因**

### 1.2 设计理念
将欧赔理论（实盘/韬盘、平赔桥梁、两项分一项等）转化为**机器可判定的公式规则**，实现：
- ✅ **输入标准化**：骨架区间/点 + 初赔 + 即时赔
- ✅ **计算自动化**：Δodds、Δp、Δmove等特征自动计算
- ✅ **规则可配置**：通过YAML文件配置规则，无需改代码
- ✅ **输出结构化**：单项推荐 + 置信度 + 解释

## 三、核心组件详解

### 3.1 特征计算引擎（features.py）

#### 功能
计算所有用于规则判断的数学特征值。

#### 核心函数

**1. `skeleton_point_and_width(skeleton)`**
- **输入**：骨架定义（区间或标准点）
  ```python
  {"type": "range", "H": [1.69, 1.88], "D": [3.57, 3.75], "A": [3.89, 4.73]}
  或
  {"type": "point", "H": 1.785, "D": 3.66, "A": 4.31}
  ```
- **输出**：骨架点M和宽度W
  ```python
  M = {"H": 1.785, "D": 3.66, "A": 4.31}
  W = {"H": 0.19, "D": 0.18, "A": 0.84}  # 如果是点则为None
  ```

**2. `delta_odds(odds, M)`**
- **计算**：`Δodds_i = (O_i - M_i) / M_i`
- **用途**：判断实盘/韬盘（≤-8%为实，≥+8%为韬）

**3. `implied_probs(odds)`**
- **计算**：去水隐含概率
  ```python
  q_i = 1 / O_i
  p_i = q_i / (q_H + q_D + q_A)
  ```
- **用途**：计算概率偏移，判断庄家权重调整

**4. `delta_move(open_odds, live_odds)`**
- **计算**：`Δmove_i = (O_live_i - O_open_i) / O_open_i`
- **用途**：判断变盘方向（确认走强/反做诱导）

**5. `pick_fav_dog(M)`**
- **逻辑**：自动识别热门方向（fav）和冷门方向（dog）
- **规则**：骨架点低赔方向 = 热门方向

**6. `compute_all_features(skeleton, odds_open, odds_live)`**
- **功能**：一次性计算所有特征值
- **返回**：包含所有计算结果的字典

---

### 3.2 规则引擎（rules.py）

#### 功能
加载YAML规则配置，执行规则匹配，格式化输出。

#### 核心函数

**1. `load_ruleset(path)`**
- **功能**：加载YAML规则文件
- **缓存**：全局缓存，避免重复加载

**2. `eval_expr(expr, ctx)`**
- **功能**：安全地求值表达式（使用simpleeval，不使用eval）
- **支持**：`<=`, `>=`, `or`, `and`, 变量访问
- **示例**：`"delta_odds_live_dog <= real"`

**3. `run_rules(ruleset, ctx)`**
- **功能**：执行规则集，返回第一个匹配的规则
- **逻辑**：按顺序检查每条规则，所有条件满足即返回

**4. `format_output(output, fav, dog, d_live, thresholds)`**
- **功能**：格式化规则输出，替换占位符
- **处理**：
  - `{fav}` → 实际热门方向（H或A）
  - `{dog}` → 实际冷门方向（A或H）
  - `fav_if_fav_real_else_dog` → 根据fav是否实盘决定

---

### 3.3 规则配置文件（ruleset_v1.yaml）

#### 结构

```yaml
version: "ruleset_v1.2"

thresholds:
  tao: 0.08              # Δodds >= +8% 认为韬
  real: -0.08           # Δodds <= -8% 认为实
  draw_spill_pp: 0.02  # Δp(D) >= +2pp 平局分洪
  draw_block_pp: -0.02 # Δp(D) <= -2pp 阻平
  move_confirm: -0.03   # Δmove <= -3% 确认走强
  move_reverse: 0.03    # Δmove >= +3% 反做/诱导

rules:
  - id: "规则ID"
    when:
      all:
        - "条件1"
        - "条件2"
    output:
      pick: "推荐赛果"
      hedge: "防守建议"
      confidence_base: 70
      intent: "意图描述"
      explain:
        - "解释1"
        - "解释2"
```

#### 核心规则模式

**1. DogReal+DrawSpill+FavTao**
- **条件**：弱势方向实盘 + 平分洪 + 热门方向韬盘
- **输出**：推荐弱势方向（dog），防平

**2. FavReal+DogTao**
- **条件**：热门方向实盘 + 冷门方向韬盘
- **输出**：推荐热门方向（fav）

**3. FavReal+DrawSpill**
- **条件**：热门方向实盘 + 平分洪
- **输出**：推荐热门方向（fav），防平

**4. DrawBlock+EdgeReal**
- **条件**：阻平 + 一侧实盘
- **输出**：推荐实盘方向，分胜负

**5. FallbackByDeltaP**
- **条件**：总是匹配（作为后备）
- **输出**：基于Δp最大项判断

### 3.4 解释生成器（explain.py）

#### 功能
将计算结果转换为可读的解释文本。

#### 核心函数

**1. `generate_explain(pattern, computed, rule_explain)`**
- **功能**：生成解释文本列表
- **内容**：
  - 赔率偏移解释（实/韬判断）
  - 概率偏移解释（平分洪/阻平）
  - 规则中定义的解释

**2. `format_intent_summary(pattern, intent, pick, hedge)`**
- **功能**：格式化意图摘要
- **格式**：`意图描述；倾向{赛果}，{防守建议}`

---

### 3.5 数据提取辅助（odds_intent_helper.py）

#### 功能
从现有比赛分析数据中提取骨架和赔率。

#### 核心函数

**1. `extract_skeleton_from_company_data(company_data)`**
- **功能**：从公司数据中提取骨架区间
- **解析**：从字符串`"实开[1.69, 1.88]"`中提取`[1.69, 1.88]`
- **返回**：`{"type": "range", "H": [1.69, 1.88], ...}`

**2. `extract_odds_from_company_data(company_data)`**
- **功能**：从公司数据中提取初赔和即时赔
- **验证**：确保所有赔率不为None且>0
- **返回**：`{"open": {"H": 2.10, ...}, "live": {"H": 2.20, ...}}`

**3. `prepare_odds_intent_input(match_analysis_data, company_id)`**
- **功能**：准备完整的分析输入
- **参数**：`company_id`（115=威廉, 80=澳门, 432=马会等）
- **返回**：包含skeleton、odds_open、odds_live的字典

---

### 3.6 主服务（odds_intent_service.py）

#### 功能
协调所有组件，提供完整的分析流程。

#### 核心函数

**1. `analyze_odds_intent(match_id, skeleton, odds_open, odds_live, context)`**
- **流程**：
  1. 计算所有特征值
  2. 加载规则集
  3. 构建执行上下文
  4. 执行规则匹配
  5. 计算置信度
  6. 生成解释
  7. 确定单项推荐

**2. `calculate_confidence(pick, computed, confidence_base, thresholds)`**
- **计算逻辑**：
  - 基础分：规则中定义的`confidence_base`
  - 偏移强度加分：`abs(Δp_pick) * 200`（最多+20）
  - 变盘确认：继续走强+10，反做-10
  - RTP异常惩罚：-8
  - 最终限制在0-100

**3. `determine_single_pick(pick, computed, exclude_mode)`**
- **功能**：确定单项推荐或排除最不可能的
- **模式1（exclude_mode=False）**：返回最优单项
- **模式2（exclude_mode=True）**：排除最不可能的（Δp最小），从剩余两个中选择最优

## 五、使用示例

### 5.1 基本使用（默认模式）

```python
from application.services.odds_intent_service import analyze_odds_intent
from application.services.odds_intent_helper import prepare_odds_intent_input
from application.services.match_analysis_service import get_match_analysis_data

# 1. 获取比赛分析数据
analysis_data = get_match_analysis_data("123456")

# 2. 准备输入（使用威廉，company_id=115）
intent_input = prepare_odds_intent_input(analysis_data['data'], company_id=115)

# 3. 执行分析
result = analyze_odds_intent(
    match_id="123456",
    skeleton=intent_input['skeleton'],
    odds_open=intent_input['odds_open'],
    odds_live=intent_input['odds_live']
)

# 4. 获取结果
print(f"推荐: {result['pick']}")
print(f"置信度: {result['confidence']}%")
print(f"原因: {result['pick_reason']}")
```

### 5.2 排除模式

```python
result = analyze_odds_intent(
    match_id="123456",
    skeleton=intent_input['skeleton'],
    odds_open=intent_input['odds_open'],
    odds_live=intent_input['odds_live'],
    context={'exclude_mode': True}  # 启用排除模式
)

# 结果会包含exclude字段
print(f"推荐: {result['pick']}")
print(f"排除: {result['exclude']}")  # 最不可能的选项
```

## 六、关键设计决策

### 6.1 为什么使用公司ID而不是名称？
- **稳定性**：ID不会因语言/编码问题变化
- **精确性**：避免中文名称匹配错误
- **扩展性**：新增公司只需添加ID映射

### 6.2 为什么输出单项而不是组合？
- **明确性**：单项推荐更直接，避免歧义
- **实用性**：用户需要的是具体选择，不是范围
- **可扩展**：通过`exclude_mode`提供排除功能

### 6.3 为什么使用YAML配置规则？
- **可维护性**：业务人员可直接修改规则，无需改代码
- **版本控制**：规则变更可追踪
- **灵活性**：支持多套规则集，可热切换

### 6.4 为什么使用simpleeval而不是eval？
- **安全性**：simpleeval是安全的表达式求值器，不会执行危险代码
- **可控性**：只支持数学运算和比较，不支持函数调用

## 七、扩展指南

### 7.1 添加新规则

在`ruleset_v1.yaml`中添加：

```yaml
rules:
  - id: "新规则名称"
    when:
      all:
        - "delta_odds_live_fav <= real"
        - "delta_p_live_D >= draw_spill_pp"
    output:
      pick: "{fav}"
      hedge: "D"
      confidence_base: 75
      intent: "规则意图描述"
      explain:
        - "解释1"
        - "解释2"
```

### 7.2 调整阈值

修改`ruleset_v1.yaml`中的`thresholds`：

```yaml
thresholds:
  tao: 0.10        # 调整为10%
  real: -0.10      # 调整为-10%
  # ...
```

### 7.3 添加新特征

1. 在`features.py`中添加计算函数
2. 在`compute_all_features`中调用
3. 在规则表达式中使用新特征

## 八、常见问题

### Q1: 为什么找不到公司数据？
**A**: 检查`company_id`是否正确，确保比赛数据中包含该公司的分析数据。

### Q2: 为什么规则不匹配？
**A**: 
- 检查阈值是否合理
- 查看计算特征值是否在预期范围
- 确认规则表达式语法正确

### Q3: 如何提高置信度？
**A**: 
- 调整规则中的`confidence_base`
- 优化阈值设置
- 添加更多确认条件

### Q4: 骨架区间如何获取？
**A**: 系统自动从公司分析数据的`homeRange`、`drawRange`、`awayRange`字段中提取。
