# 接口500错误排查报告

## 问题概述

小程序进入时发现接口返回500错误，影响用户体验。

## 发现的问题

### 1. 错误日志不完整 ⚠️

**问题**：`get_today_matches` 函数的异常处理中缺少 `exc_info=True`，导致无法看到详细的错误堆栈

**修复**：已添加 `exc_info=True` 到错误日志记录中

### 2. 性能监控数据异常（已修复）✅

**问题**：性能监控显示的 `app` 时间异常大（1766899227.846s）

**修复**：已修复 `utils/performance_monitor.py`，添加了异常时间检测

### 3. 定时任务 datetime 错误（已修复）✅

**问题**：定时任务中使用了 `datetime.now()` 但没有导入 `datetime`

**修复**：已修复 `services/scheduled_data_updater.py`，使用 `now()` 函数替代

## 受影响的接口

1. **`/api/matches/today`** - 需要登录的今日比赛接口
   - 状态：返回500错误
   - 日志：缺少详细错误堆栈

2. **`/api/miniprogram/user`** - 小程序用户信息接口
   - 状态：返回500错误
   - 日志：已有详细错误堆栈（`exc_info=True`）

## 已实施的修复

### 1. 增强错误日志记录

**文件**：`application/routes/web.py`

**修改**：
- `get_today_matches` 函数：添加 `exc_info=True`
- `get_public_today_matches` 函数：添加 `exc_info=True`

**效果**：现在可以查看完整的错误堆栈，便于定位问题

### 2. 修复性能监控

**文件**：`utils/performance_monitor.py`

**修改**：添加异常时间检测和重新计算逻辑

**效果**：性能监控数据更准确

## 下一步排查建议

### 1. 查看详细错误日志

修复后，当接口再次出现500错误时，可以查看完整的错误堆栈：

```bash
tail -100 logs/oddsmind.log | grep -A 20 "获取今日比赛失败"
tail -100 logs/errors.log | grep -A 20 "get_today_matches"
```

### 2. 检查可能的原因

1. **数据库连接问题**：检查数据库是否正常连接
2. **配置问题**：检查 `MONITORING_DAYS`、`MONITORED_LEAGUES` 等配置
3. **认证问题**：检查 `@login_required` 装饰器是否正常工作
4. **初始化问题**：检查 `@ensure_initialized` 装饰器是否正常

### 3. 对比公开接口

公开接口 `/api/public/matches/today` 正常工作，说明：
- 数据库连接正常
- SQL查询逻辑正常
- 问题可能在于：
  - 认证逻辑（`@login_required`）
  - 初始化逻辑（`@ensure_initialized`）
  - 用户权限检查

### 4. 测试建议

1. **测试认证流程**：
   ```bash
   # 测试带token的请求
   curl -H "Authorization: Bearer <token>" http://localhost:8889/api/matches/today
   ```

2. **测试初始化状态**：
   - 检查应用是否已正确初始化
   - 查看初始化日志

3. **对比测试**：
   - 测试公开接口（应该正常）
   - 测试需要登录的接口（可能失败）

## 临时解决方案

如果问题持续存在，建议：

1. **使用公开接口**：小程序优先使用 `/api/public/matches/today`
2. **添加重试机制**：前端添加自动重试逻辑
3. **降级处理**：接口失败时使用缓存数据
