# 激活码重复使用问题修复

## 🔍 问题分析

**问题现象：**
- 激活码 `TEST1D` 可以重复使用
- `used_count` 没有正确更新

**根本原因：**
1. **并发问题**：多个请求同时验证时，都通过了验证（`used_count < max_uses`），然后都执行了激活
2. **执行顺序问题**：先激活用户，再更新使用次数，中间可能被其他请求插入
3. **缺少原子性**：验证和使用不是原子操作

## ✅ 修复方案

### 1. 调整执行顺序（先使用，再激活）

**修改前：**
```python
# 1. 验证邀请码
validate_invite_code(invite_code)

# 2. 激活用户
activate_user(openid, invite_code, expires_days)

# 3. 使用邀请码（增加使用次数）
use_invite_code(invite_code)  # ❌ 太晚了，可能已经被其他请求使用了
```

**修改后：**
```python
# 1. 验证邀请码
validate_invite_code(invite_code)

# 2. 先使用邀请码（增加使用次数）✅ 提前使用，防止并发
use_invite_code(invite_code)

# 3. 再次验证（防止并发问题）
validate_invite_code(invite_code)

# 4. 激活用户
activate_user(openid, invite_code, expires_days)
```

### 2. 使用数据库事务和行锁（推荐）

**更安全的方案：**
```python
from app_database import get_connection

def activate_user_with_invite_code(openid: str, invite_code: str, expires_days: int):
    """原子性操作：验证、使用、激活"""
    conn = get_connection()
    try:
        with conn.cursor() as cursor:
            # 1. 使用行锁获取邀请码信息
            cursor.execute("""
                SELECT max_uses, used_count, is_active, expires_at
                FROM invite_codes
                WHERE code = %s FOR UPDATE
            """, (invite_code,))
            
            invite_info = cursor.fetchone()
            if not invite_info:
                raise ValueError("邀请码不存在")
            
            # 2. 验证邀请码
            if not invite_info['is_active']:
                raise ValueError("邀请码已被禁用")
            
            if invite_info['used_count'] >= invite_info['max_uses']:
                raise ValueError("邀请码使用次数已达上限")
            
            # 3. 使用邀请码（在事务中）
            cursor.execute("""
                UPDATE invite_codes
                SET used_count = used_count + 1
                WHERE code = %s
            """, (invite_code,))
            
            # 4. 激活用户
            expires_at = datetime.now() + timedelta(days=expires_days)
            cursor.execute("""
                UPDATE miniprogram_users
                SET is_activated = TRUE,
                    activated_at = NOW(),
                    expires_at = %s,
                    invite_code_used = %s
                WHERE openid = %s
            """, (expires_at, invite_code, openid))
            
            conn.commit()
            return True
    except Exception as e:
        conn.rollback()
        raise
    finally:
        conn.close()
```

## ⚠️ 注意事项

1. **并发问题**：
   - 当前修复可以减少并发问题，但不能完全避免
   - 如果需要完全避免，需要使用数据库事务和行锁

2. **回滚问题**：
   - 如果激活用户失败，使用次数已经增加，无法回滚
   - 这是设计上的权衡，确保激活码不会被浪费

3. **建议**：
   - 对于高并发场景，建议使用数据库事务和行锁
   - 当前修复适用于低并发场景
