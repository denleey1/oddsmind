# 服务启动验证指南

重启应用后，使用以下方法验证所有服务是否正常启动。

## 方法1：使用综合检查脚本（推荐）

运行综合检查脚本，一次性检查所有服务状态：

```bash
cd /home/ubuntu/oddsmind
source venv/bin/activate
python check_all_services.py
```

这个脚本会检查：
- ✅ 定时数据更新服务（ScheduledDataUpdater）
- ✅ 全局调度器（APScheduler）
- ✅ 监控服务
- ✅ 联赛状态监控
- ✅ 应用整体状态

## 方法2：查看启动日志

检查应用启动日志，确认所有服务都正常启动：

```bash
# 查看最近的启动日志
tail -100 logs/oddsmind.log | grep -i -E "(定时数据更新服务|ScheduledDataUpdater|定时任务配置完成|调度器已启动|应用初始化完成)"

# 或者实时查看日志
tail -f logs/oddsmind.log | grep -i -E "(定时|scheduler|监控|初始化)"
```

**应该看到的日志**：
```
立即启动定时任务服务...
定时数据更新服务已启动
定时任务配置完成
任务计划:
  23:59 - 联赛数据更新
  00:59 - 赔率数据更新
  01:59 - 广义实力计算
  03:00 - 数据清理（保留7天）
定时任务调度器已启动
应用初始化完成 - 调度器和监控服务已启动
```

## 方法3：通过API检查（如果已登录）

如果应用已启动且可以访问API：

```bash
# 检查调度器状态
curl -X GET http://localhost:5000/api/v1/scheduler/status

# 检查监控状态
curl -X GET http://localhost:5000/api/v1/monitor/status

# 健康检查
curl -X GET http://localhost:5000/health
```

## 方法4：检查进程和线程

检查应用进程是否在运行：

```bash
# 检查应用进程
ps aux | grep "app.py" | grep -v grep

# 检查Python进程的线程数（应该有很多线程，包括调度器线程）
ps -eLf | grep "app.py" | wc -l
```

## 常见问题排查

### 问题1：定时数据更新服务未启动

**症状**：检查脚本显示"定时数据更新服务未创建"或"未运行"

**解决方法**：
```bash
# 手动启动定时任务服务
cd /home/ubuntu/oddsmind
source venv/bin/activate
python start_scheduler.py
```

### 问题2：调度器未运行

**症状**：调度器显示"未运行"

**可能原因**：
- 应用未完全初始化
- 调度器启动失败

**解决方法**：
1. 检查日志中的错误信息
2. 确认应用已完全启动
3. 等待10分钟让延迟初始化完成

### 问题3：任务没有下次执行时间

**症状**：任务显示"下次执行: N/A"

**可能原因**：
- 时区设置不正确
- 任务配置有问题

**解决方法**：
1. 检查服务器时区：`timedatectl` 或 `date`
2. 确认定时任务配置中的时区设置（应该是 Asia/Shanghai）
