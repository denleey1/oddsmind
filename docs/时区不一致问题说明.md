# 时区不一致问题说明（UTC vs UTC+8）

## 问题概述

如果代码中混用 UTC 和 UTC+8（Asia/Shanghai），会导致严重的时间计算错误。

## 具体问题

### 1. **时间比较错误（8小时误差）**

**场景**：账号过期时间判断

```python
# ❌ 错误示例：存储用UTC+8，比较用UTC
expires_at = datetime.now() + timedelta(days=1)  # 2025-11-28 18:00:00 (UTC+8)
now_utc = datetime.now(timezone.utc)  # 2025-11-28 10:00:00 (UTC)

# 比较时：2025-11-28 18:00:00 < 2025-11-28 10:00:00 ❌ 错误！
# 实际上应该是：2025-11-28 10:00:00 < 2025-11-28 10:00:00 ✅
```

**影响**：
- 账号提前8小时被判定为过期
- 或者账号过期后8小时还能使用

### 2. **数据查询错误**

**场景**：查询"今天"的比赛

```python
# ❌ 错误示例
today_start = datetime.now().replace(hour=0, minute=0)  # UTC+8的今天00:00
# 数据库存储的是UTC时间
# 查询时：UTC+8的00:00 = UTC的前一天16:00
# 结果：查询到的是"昨天"的数据
```

**影响**：
- 查询不到当天的数据
- 或者查询到错误日期的数据

### 3. **定时任务执行时间错误**

**场景**：定时任务设置为每天23:59执行

```python
# ❌ 错误示例
scheduler = BackgroundScheduler(timezone='Asia/Shanghai')
# 但代码中使用 datetime.now(timezone.utc) 判断时间
# 结果：任务在错误的时间执行（提前或延后8小时）
```

**影响**：
- 定时任务在错误的时间执行
- 数据更新不及时

### 4. **日志时间混乱**

**场景**：日志记录时间

```python
# ❌ 错误示例
logger.info(f"操作时间: {datetime.now()}")  # UTC+8
logger.info(f"操作时间: {datetime.now(timezone.utc)}")  # UTC
# 两种时间混在一起，无法判断真实时间
```

**影响**：
- 日志时间不一致，难以排查问题
- 无法准确追踪操作时间

### 5. **前端显示错误**

**场景**：前端显示时间

```python
# ❌ 后端返回UTC时间
return {'time': datetime.now(timezone.utc).isoformat()}  
# 前端显示：2025-11-28T10:00:00Z
# 用户看到：10:00（以为是本地时间）
# 实际应该是：18:00（UTC+8）
```

**影响**：
- 用户看到的时间比实际时间早8小时
- 用户体验差

## 实际案例

### 案例1：账号过期判断错误

```python
# 存储时（UTC+8）
expires_at = datetime.now() + timedelta(days=1)
# 结果：2025-11-28 18:00:00 (UTC+8，无时区信息)

# 判断时（假设是UTC）
now_utc = datetime.now(timezone.utc)
# 结果：2025-11-28 10:00:00 (UTC)

# 比较
if expires_at < now_utc:  # 2025-11-28 18:00 < 2025-11-28 10:00 ❌
    # 误判为已过期！
```

**修复后**：
```python
# 统一使用UTC+8
from utils.timezone_utils import now
expires_at = now() + timedelta(days=1)
now_local = now()
if expires_at < now_local:  # ✅ 正确比较
```

### 案例2：查询今天的数据

```python
# ❌ 错误：混用时区
today = datetime.now().date()  # UTC+8的今天
# 数据库存储的是UTC时间
# 查询：WHERE date = '2025-11-28' (UTC+8)
# 实际数据库：2025-11-27 16:00:00 (UTC) = 2025-11-28 00:00:00 (UTC+8)
# 结果：查不到数据
```

**修复后**：
```python
# ✅ 正确：统一时区
from utils.timezone_utils import now
today = now().date()  # UTC+8的今天
# 数据库也使用UTC+8时区
# 查询正确
```

## 解决方案

### 1. **统一使用一个时区**

推荐：统一使用 **Asia/Shanghai (UTC+8)**

```python
from utils.timezone_utils import now, to_timezone_aware

# 获取当前时间（UTC+8）
current_time = now()

# 转换为时区感知对象
aware_dt = to_timezone_aware(naive_dt)
```

### 2. **数据库时区设置**

```python
# 数据库连接时设置时区
cursor.execute("SET time_zone = '+08:00'")
```

### 3. **API返回时间格式**

```python
# 返回给前端的时间去掉时区信息（前端按本地时区解析）
def format_datetime_for_frontend(dt):
    if dt and dt.tzinfo:
        return dt.replace(tzinfo=None).isoformat()
    return dt.isoformat() if dt else None
```

## 总结

**时区不一致的核心问题**：
1. **8小时误差**：所有时间计算都会有8小时偏差
2. **日期错误**：跨日期查询会查错日期
3. **逻辑错误**：过期判断、定时任务等都会出错
4. **用户体验差**：显示时间不准确

**最佳实践**：
- ✅ 统一使用一个时区（推荐UTC+8）
- ✅ 数据库时区与应用时区一致
- ✅ 所有时间比较使用同一时区
- ✅ API返回时间格式统一
