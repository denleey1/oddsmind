# 定时任务时区修复说明

## 问题诊断

**问题现象**：广义实力计算任务（每天凌晨01:59执行）没有自动执行，虽然：
- 调度器显示运行中 ✅
- 任务已正确注册 ✅
- 任务本身可以手动执行 ✅

**根本原因（第一次修复）**：
`CronTrigger` 没有明确指定时区参数，虽然调度器初始化时设置了 `timezone='Asia/Shanghai'`，但 `CronTrigger` 可能需要明确指定时区才能正确工作。

**根本原因（第二次修复 - 2025-11-19）**：
虽然定时任务被正确触发并执行，但 `_calculate_strength_task` 方法在存在 `coordinator` 时会调用 `coordinator.process_completed_matches()`，而该方法已经跳过了广义实力计算（代码注释："Skip broad strength recalculation"）。因此任务虽然执行成功，但实际上并没有计算广义实力数据。

## 修复内容

### 第一次修复：时区问题

#### 修改文件
`services/scheduled_data_updater.py`

#### 修改内容
为所有 `CronTrigger` 明确指定 `timezone='Asia/Shanghai'` 参数：

**修改前**：
```python
trigger=CronTrigger(hour=1, minute=59)
```

**修改后**：
```python
trigger=CronTrigger(hour=1, minute=59, timezone='Asia/Shanghai')
```

#### 修改的任务
1. ✅ `daily_leagues_update` - 每日23:59联赛数据更新
2. ✅ `daily_odds_update` - 每日00:59赔率数据更新
3. ✅ `daily_strength_calculation` - 每日01:59广义实力计算
4. ✅ `daily_data_cleanup` - 每日03:00数据清理

### 第二次修复：任务执行逻辑问题（2025-11-19）

#### 修改文件
`services/scheduled_data_updater.py` - `_calculate_strength_task` 方法

#### 修改内容
移除了对 `coordinator.process_completed_matches()` 的调用，直接执行广义实力计算命令：

**修改前**：
```python
if self.coordinator:
    summary = self.coordinator.process_completed_matches()
    # ... 记录日志
else:
    # 执行广义实力计算命令
    cmd = [...]
    # ...
```

**修改后**：
```python
# 直接执行广义实力计算命令（不再使用coordinator.process_completed_matches()，
# 因为该方法已跳过广义实力计算）
cmd = [
    os.path.join(self.project_root, 'venv', 'bin', 'python'),
    os.path.join(self.project_root, 'main.py'),
    'calculate-strength',
    '--league-group', 'monitored',
    '--max-workers', '4'
]
# ... 执行命令
```

### 额外改进
增强了任务执行监听器的日志记录，现在会记录：
- 任务执行成功的时间戳
- 任务执行失败的详细异常信息

## 下一步操作

### 1. 重启应用（应用修复）

需要重启正在运行的Flask应用，让修复生效：

```bash
# 查找应用进程
ps aux | grep "app.py" | grep -v grep

# 重启应用（根据你的部署方式）
# 如果使用systemd:
sudo systemctl restart oddsmind

# 或者手动重启:
# 1. 停止当前进程
kill <进程ID>

# 2. 重新启动
cd /home/ubuntu/oddsmind
nohup python app.py > /dev/null 2>&1 &
```

### 2. 验证修复

重启后，检查：

1. **查看日志确认任务已注册**：
```bash
grep "定时任务配置完成" logs/oddsmind.log | tail -1
```

2. **等待下次执行时间验证**：
- 下次执行时间应该是：每天凌晨 01:59:00 (Asia/Shanghai)
- 执行后查看日志：
```bash
grep "任务.*执行成功\|开始执行.*广义实力\|广义实力计算完成" logs/oddsmind.log | tail -10
```
- 确认任务执行时间应该较长（通常需要几分钟到几十分钟），而不是只有几秒

3. **或者手动触发一次测试**：
```bash
curl -X POST http://localhost:8889/api/v1/scheduler/tasks/run \
  -H "Content-Type: application/json" \
  -d '{"task_name": "strength_calculation"}'
```

## 预期效果

修复后，定时任务应该能够：
- ✅ 在正确的时间（每天凌晨01:59，Asia/Shanghai时区）自动执行
- ✅ 在日志中记录执行成功/失败的信息
- ✅ 更新数据库中的广义实力数据

## 注意事项

1. **时区一致性**：确保系统时区、调度器时区和 CronTrigger 时区都设置为 `Asia/Shanghai`
2. **日志监控**：建议定期检查日志，确认任务正常执行
3. **手动备份**：在修复生效前，可以手动执行一次任务确保数据更新
