# 502 Bad Gateway 错误诊断与修复指南

## 🔍 错误分析

**错误信息：** `POST https://oddsmind.top/api/miniprogram/login 502 (Bad Gateway)`

**502 错误的含义：**
- 网关/代理服务器（如 Nginx）无法从上游服务器（Flask 应用）获取有效响应
- 通常表示后端服务未运行、崩溃或无法响应请求

---

## 📋 诊断步骤

### 1. 检查后端服务状态

```bash
# 检查服务是否运行
systemctl status oddsmind

# 或者检查进程
ps aux | grep python | grep app.py

# 检查端口是否监听
netstat -tlnp | grep :8889
# 或
ss -tlnp | grep :8889
```

**如果服务未运行：**
```bash
# 启动服务
systemctl start oddsmind

# 或手动启动
cd /home/ubuntu/oddsmind
source venv/bin/activate  # 激活虚拟环境
python app.py
```

---

### 2. 检查后端日志

```bash
# 查看应用日志
tail -f /home/ubuntu/oddsmind/logs/app.log

# 或查看系统日志
journalctl -u oddsmind -f

# 查看最近的错误
tail -n 100 /home/ubuntu/oddsmind/logs/app.log | grep -i error
```

**常见错误：**
- `ModuleNotFoundError` - 缺少 Python 模块
- `ImportError` - 导入错误
- `Database connection failed` - 数据库连接失败
- `Port already in use` - 端口被占用

---

### 3. 检查代码导入错误

```bash
cd /home/ubuntu/oddsmind
source venv/bin/activate

# 测试导入小程序路由
python3 -c "from application.routes.miniprogram import miniprogram_bp; print('OK')"
```

**如果出现导入错误，可能的原因：**
1. 虚拟环境未激活
2. 缺少依赖包
3. 代码语法错误

---

### 4. 检查 Nginx 配置

```bash
# 检查 Nginx 配置
sudo nginx -t

# 查看 Nginx 错误日志
sudo tail -f /var/log/nginx/error.log

# 检查 Nginx 配置中的 upstream 设置
cat /etc/nginx/sites-available/oddsmind.conf | grep -A 5 upstream
```

**Nginx 配置示例：**
```nginx
upstream flask_app {
    server 127.0.0.1:8889;  # 确保端口正确
}

server {
    location /api/ {
        proxy_pass http://flask_app;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

---

### 5. 直接测试后端接口

```bash
# 测试本地接口（绕过 Nginx）
curl -X POST http://localhost:8889/api/miniprogram/login \
  -H "Content-Type: application/json" \
  -d '{"code":"test_code"}'

# 如果本地可以，说明问题在 Nginx 配置
# 如果本地也不行，说明问题在后端代码
```

## 🔧 常见问题及解决方案

### 问题 1: 服务未运行

**症状：** `systemctl status oddsmind` 显示 inactive

**解决方案：**
```bash
# 启动服务
sudo systemctl start oddsmind

# 设置开机自启
sudo systemctl enable oddsmind

# 检查启动日志
sudo journalctl -u oddsmind -n 50
```

---

### 问题 2: 导入错误（ModuleNotFoundError）

**症状：** 日志中出现 `ModuleNotFoundError: No module named 'flask'`

**解决方案：**
```bash
cd /home/ubuntu/oddsmind

# 激活虚拟环境
source venv/bin/activate

# 安装依赖
pip install -r requirements.txt

# 特别检查新添加的依赖
pip install PyJWT==2.8.0
```

---

### 问题 3: 代码语法错误

**症状：** 服务启动时立即崩溃

**解决方案：**
```bash
# 检查 Python 语法
python3 -m py_compile application/routes/miniprogram.py

# 检查所有相关文件
python3 -m py_compile utils/jwt_helper.py
python3 -m py_compile utils/miniprogram_db.py
```

---

### 问题 4: 数据库连接失败

**症状：** 日志中出现数据库连接错误

**解决方案：**
```bash
# 检查数据库服务
sudo systemctl status mysql

# 测试数据库连接
mysql -u root -p -e "USE oddsmind; SHOW TABLES;"

# 检查数据库表是否存在
mysql -u root -p -e "USE oddsmind; SHOW TABLES LIKE 'miniprogram%';"
```

**如果表不存在，需要创建：**
```bash
# 运行数据库初始化脚本（如果有）
# 或手动执行 SQL
mysql -u root -p oddsmind < create_tables.sql
```

---

### 问题 5: 端口被占用

**症状：** `Address already in use`

**解决方案：**
```bash
# 查找占用端口的进程
lsof -i :8889
# 或
netstat -tlnp | grep :8889

# 杀死进程
kill -9 <PID>

# 或修改配置文件使用其他端口
```

---

### 问题 6: 环境变量未设置

**症状：** 功能异常但服务能启动

**解决方案：**
```bash
# 检查环境变量文件
cat /home/ubuntu/oddsmind/oddsmind.env | grep -E "JWT_SECRET|WECHAT"

# 如果不存在，添加环境变量
echo "JWT_SECRET=your_secret_key_here" >> /home/ubuntu/oddsmind/oddsmind.env
echo "WECHAT_APPID=your_appid" >> /home/ubuntu/oddsmind/oddsmind.env
echo "WECHAT_APPSECRET=your_secret" >> /home/ubuntu/oddsmind/oddsmind.env

# 重启服务
sudo systemctl restart oddsmind
```

## 💡 预防措施

1. **设置服务监控**
   - 使用 systemd 自动重启
   - 配置健康检查

2. **日志轮转**
   - 定期清理日志
   - 监控日志大小

3. **依赖管理**
   - 使用 requirements.txt
   - 定期更新依赖

4. **错误处理**
   - 添加完善的异常处理
   - 记录详细错误信息

## 📞 如果问题仍然存在

1. **收集信息**
   - 服务状态输出
   - 最近 100 行日志
   - Nginx 错误日志
   - 系统资源使用情况

2. **检查系统资源**
   ```bash
   # 内存使用
   free -h
   
   # CPU 使用
   top
   
   # 磁盘空间
   df -h
   ```

3. **查看完整错误堆栈**
   - 在代码中添加更详细的日志
   - 使用调试模式运行
