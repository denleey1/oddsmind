# 澳超数据问题诊断报告

## 问题概述

通过直接查询数据库，发现了澳超数据的多个严重问题，导致广义实力计算无法正常进行。

## 发现的问题

### 1. 轮次数据严重缺失 ❌

**问题**：157场比赛中，156场比赛的 `round_number` 字段为 `NULL`

**数据统计**：
- 总比赛数：157场
- 有轮次数据的比赛：1场（match_id=2780161, round_number=1）
- NULL轮次的比赛：156场（99.36%）

**影响**：
- 广义实力计算依赖轮次数据来确定"近况轮次"
- 轮次数据缺失会导致计算逻辑错误
- `strength_service.py` 第49行：`current_round = int(matches_df['round_number'].max())` 会返回 `NaN`

### 2. 赔率数据覆盖率极低 ❌

**问题**：已完成比赛的赔率数据覆盖率只有 8.77%，远低于 80% 阈值

**数据统计**：
- 已完成比赛：57场
- 有赔率数据的比赛：5场
- 覆盖率：8.77%
- 阈值要求：80%

**影响**：
- `strength_repository.py` 第101行的覆盖率检查会过滤掉所有公司
- 没有公司能通过覆盖率检查，广义实力计算被完全跳过
- 导致澳超没有正确的广义实力数据

### 3. 广义实力数据异常 ❌

**问题**：广义实力数据只有2支球队，且存在大量重复记录

**数据统计**：
- 有数据的公司：119家
- 有数据的球队：只有2支（墨尔本城14549、墨尔本胜利2901）
- 实际应该有：12支球队
- 每支球队的重复记录：27条（异常）

**具体数据**：
- 墨尔本城（14549）：119家公司都有数据，但都是重复的
- 墨尔本胜利（2901）：部分公司有数据
- 其他10支球队：完全没有数据

**影响**：
- 广义实力数据不完整，无法用于分析
- 重复数据可能是之前计算时的错误导致的

### 4. 已完成比赛分析

**最近20场已完成比赛**：
- 所有比赛的 `round_number` 都是 `NULL`
- 大部分比赛没有赔率数据（companies_count=0）
- 只有少数比赛有赔率数据（如 match_id=2871705 有176家公司）

## 根本原因分析

### 原因1：数据采集问题
- 澳超的比赛数据在采集时没有正确设置 `round_number`
- 可能是数据源本身没有轮次信息，或者采集逻辑有问题

### 原因2：赔率数据采集不完整
- 已完成比赛的赔率数据覆盖率只有8.77%
- 可能是赔率采集任务没有正常运行，或者数据源问题

### 原因3：广义实力计算被跳过
- 由于覆盖率不足，所有公司都被过滤掉
- 导致没有正确的广义实力数据
- 现有的数据可能是之前某次不完整的计算留下的

## 解决方案

### 方案1：修复轮次数据（必须）🔴

**步骤**：
1. 检查数据源是否有轮次信息
2. 如果有，更新采集逻辑，确保 `round_number` 被正确设置
3. 如果没有，需要根据比赛时间和其他信息推算轮次

**SQL查询示例**：
```sql
-- 检查是否有其他字段可以推算轮次
SELECT match_id, match_time, round_number, match_status
FROM matches
WHERE league_id = 273
ORDER BY match_time;
```

### 方案2：提高赔率数据覆盖率（必须）🔴

**步骤**：
1. 检查赔率采集任务是否正常运行
2. 检查已完成比赛是否有赔率数据源
3. 重新采集已完成比赛的赔率数据

**SQL查询示例**：
```sql
-- 检查哪些已完成比赛没有赔率数据
SELECT m.match_id, m.match_time, m.match_status,
       COUNT(DISTINCT eo.company_id) as companies_count
FROM matches m
LEFT JOIN european_odds eo ON eo.match_id = m.match_id
WHERE m.league_id = 273 AND m.match_status = 'finished'
GROUP BY m.match_id, m.match_time, m.match_status
HAVING companies_count = 0
ORDER BY m.match_time DESC;
```

### 方案3：清理异常广义实力数据（建议）🟡

**步骤**：
1. 删除现有的异常广义实力数据
2. 修复轮次和赔率数据后，重新计算广义实力

**SQL示例**：
```sql
-- 删除澳超的异常广义实力数据
DELETE tpr FROM team_power_ratings tpr
JOIN matches m ON (m.home_team_id = tpr.team_id OR m.away_team_id = tpr.team_id)
WHERE m.league_id = 273;
```

### 方案4：重新计算广义实力（修复后）🟢

**步骤**：
1. 修复轮次数据
2. 提高赔率数据覆盖率到80%以上
3. 运行广义实力计算命令：
```bash
python main.py calculate-strength --league-ids 273
```
