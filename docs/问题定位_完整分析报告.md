# 问题定位完整分析报告 - 逐层深入

## 问题概述

小程序接口返回500错误，需要逐层定位根本原因。

## 第一层定位：认证装饰器 datetime 未导入 ✅

### 问题发现

**文件**：`auth.py`

**问题位置**：
- 第122行：`expires_at = datetime.fromisoformat(...)`
- 第127行：`elif isinstance(expires_at, datetime) and ...`
- 第144行：`'expires_at': db_user.get('expires_at').isoformat() if ...`

**问题**：使用了 `datetime` 但没有导入

**当前导入语句**：
```python
import os
import logging
from functools import wraps
from flask import Blueprint, redirect, url_for, request, g, session, jsonify
from utils.timezone_utils import now, to_timezone_aware
```

**缺失**：❌ 没有 `from datetime import datetime`

### 错误触发流程

1. 用户请求 → `/api/miniprogram/user` 或 `/api/matches/2826215`
2. 装饰器执行 → `@login_required` 开始验证
3. JWT验证通过 → Token验证成功
4. 获取用户信息 → `get_user_by_openid(openid)` 成功
5. 检查过期时间 → `expires_at = db_user.get('expires_at')` 有值
6. 解析时间字符串 → 第122行：`datetime.fromisoformat(...)`
7. **NameError** → `NameError: name 'datetime' is not defined`
8. 异常未被捕获 → 装饰器中的异常导致500错误

### 为什么没有看到详细错误日志？

**分析**：
- 异常在装饰器内部抛出
- Flask的异常处理可能没有记录到日志
- 性能监控显示 `app=0.000s`，说明请求在认证阶段就失败了

### 验证证据

1. **性能监控数据**：
   ```
   PERF [web.get_match_detail_route] status=500 total=0.001s app=0.000s db=0.001s
   ```
   - `app=0.000s` 说明没有进入业务逻辑
   - 请求在认证阶段就失败了

2. **对比测试**：
   - ✅ `/api/public/matches/2826215` - 正常（不需要认证）
   - ❌ `/api/matches/2826215` - 失败（需要认证）

3. **代码检查**：
   - `auth.py` 中使用了 `datetime` 但没有导入
   - 第122、127、144行都使用了 `datetime`

## 第二层定位：需要检查的其他可能问题

### 2.1 异常处理不完整

**问题**：装饰器中的异常可能没有被正确捕获和记录

**位置**：`auth.py` 的 `login_required` 装饰器

**检查点**：
- 是否有 try-except 包裹整个装饰器逻辑？
- 异常是否被正确记录到日志？

### 2.2 数据库查询异常

**问题**：`get_user_by_openid` 可能抛出异常

**位置**：`utils/miniprogram_db.py` 第34行

**检查点**：
- 数据库连接是否正常？
- SQL查询是否可能失败？

### 2.3 JWT Token验证异常

**问题**：JWT Token验证可能抛出异常

**位置**：`auth.py` 第75行 `_verify_jwt_token(jwt_token)`

**检查点**：
