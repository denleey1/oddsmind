# 激活码原子性操作说明

## ✅ 已实现的原子性操作

### 问题根源

**之前的问题：**
- 激活码可以重复使用
- `used_count` 没有正确更新
- 并发请求可能导致多个用户同时使用同一个激活码

**根本原因：**
- 验证和使用不是原子操作
- 没有使用数据库事务和行锁
- 多个请求可能同时通过验证

### 解决方案

**使用数据库事务和行锁（`FOR UPDATE`）实现原子性操作：**

```python
def activate_user_with_invite_code_atomic(
    openid: str,
    invite_code: str,
    expires_days: int,
    user_id: int
) -> tuple[bool, Optional[str]]:
    """
    原子性操作：验证、使用邀请码并激活用户
    使用数据库事务和行锁确保并发安全
    """
    conn = get_connection()
    cursor = conn.cursor()
    
    try:
        # 1. 开始事务
        cursor.execute("START TRANSACTION")
        
        # 2. 使用行锁获取邀请码（FOR UPDATE 锁定行，防止并发）
        cursor.execute("""
            SELECT id, max_uses, used_count, is_active, expires_at
            FROM invite_codes
            WHERE code = %s FOR UPDATE
        """, (invite_code,))
        
        invite_info = cursor.fetchone()
        
        # 3. 验证邀请码
        if used_count >= max_uses:
            conn.rollback()
            return False, "邀请码使用次数已达上限"
        
        # 4. 使用邀请码（在事务中）
        cursor.execute("""
            UPDATE invite_codes
            SET used_count = used_count + 1
            WHERE code = %s
        """, (invite_code,))
        
        # 5. 激活用户（在事务中）
        cursor.execute("""
            UPDATE miniprogram_users
            SET is_activated = TRUE,
                activated_at = NOW(),
                expires_at = %s,
                invite_code_used = %s
            WHERE openid = %s
        """, (expires_at, invite_code, openid))
        
        # 6. 提交事务
        conn.commit()
        return True, None
        
    except Exception as e:
        conn.rollback()
        return False, f"激活失败: {str(e)}"
    finally:
        cursor.close()
        conn.close()
```

## 🔒 关键机制

### 1. 数据库事务

- **开始事务**：`START TRANSACTION`
- **提交事务**：`conn.commit()`
- **回滚事务**：`conn.rollback()`

### 2. 行锁（FOR UPDATE）

- **锁定行**：`SELECT ... FOR UPDATE`
- **防止并发**：其他请求必须等待当前事务完成
- **确保原子性**：验证、使用、激活在同一事务中

### 3. 执行顺序

```
开始事务
    ↓
锁定邀请码行（FOR UPDATE）
    ↓
验证使用次数
    ↓
使用邀请码（used_count + 1）
    ↓
激活用户
    ↓
提交事务
```

## ⚠️ 注意事项

1. **事务必须提交**：如果事务没有提交，所有更改都会回滚
2. **行锁会阻塞**：`FOR UPDATE` 会锁定行，其他请求必须等待
3. **连接必须关闭**：使用完连接后必须关闭，归还给连接池

## 🎯 优势

1. ✅ **完全避免并发问题**：使用行锁确保同一时间只有一个请求能使用激活码
2. ✅ **原子性保证**：验证、使用、激活在同一事务中，要么全部成功，要么全部失败
3. ✅ **数据一致性**：使用次数和用户状态始终保持一致
