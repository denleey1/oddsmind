# 爬虫并发优化快速参考

**实施日期**: 2025-12-28  
**核心优化**: 批量写入队列，避免数据库竞锁

---

## ✅ 已实施的优化

### 1. 批量写入队列（BatchWriter）

**文件**: `database/batch_writer.py` (新建)

**功能**:
- 将数据库写入操作从爬虫线程中分离
- 使用队列缓冲，由专门的写入线程批量处理
- 避免多线程并发写入导致的数据库竞锁

**配置参数**:
- `batch_size`: 500（每批处理500条）
- `flush_interval`: 2.0秒（每2秒刷新一次）
- `max_queue_size`: 10000（队列最大长度）

### 2. DatabaseManager 集成

**文件**: `database/manager.py`

**修改内容**:
- `__init__` 方法：添加 `use_batch_writer` 参数（默认启用）
- `bulk_upsert_odds_changes`: 优先使用队列，队列满时降级为直接写入
- `bulk_upsert_over_under_odds_changes`: 优先使用队列
- `store_multiple_odds_data`: 优先使用队列

### 3. 应用生命周期管理

**文件**: `core/runtime.py`

**修改内容**:
- `shutdown` 方法：添加 BatchWriter 优雅关闭逻辑

## ⚙️ 配置调整

### 调整批量大小

如果需要调整批量处理参数，修改 `DatabaseManager.__init__`:

```python
self.batch_writer = BatchWriter(
    self,
    batch_size=1000,        # 增加到1000
    flush_interval=1.0,     # 缩短到1秒
    max_queue_size=20000    # 增加队列大小
```

### 禁用批量写入队列

如果遇到问题需要禁用，修改 `DatabaseManager.__init__`:

```python
def __init__(self, use_batch_writer: bool = False):  # 改为 False
    # ...
```

## 🐛 故障排查

### 问题1: 队列满，数据被丢弃

**症状**: 日志中出现 "queue is full, dropping"

**解决方案**:
1. 增加 `max_queue_size`
2. 缩短 `flush_interval`
3. 增加 `batch_size`

### 问题2: 写入延迟

**症状**: 数据写入延迟超过2秒

**解决方案**:
1. 缩短 `flush_interval`（如改为1.0秒）
2. 检查数据库性能
3. 检查连接池大小

### 问题3: BatchWriter 未启动

**症状**: `db_manager.batch_writer` 为 `None`

**解决方案**:
1. 检查日志中的错误信息
2. 确认 `use_batch_writer=True`
3. 检查是否有导入错误
