# 规则优化服务使用指南

## 概述

`rule_optimizer.py` 是一个自动化规则优化服务，用于：
1. **分析规则表现**：基于回测结果统计每个规则的实际准确率
2. **发现优质规则**：从历史数据中挖掘新的高准确率规则模式
3. **淘汰低效规则**：识别表现不佳的规则，建议移除或调整
4. **持续优化**：定期运行，持续改进规则库质量

## 核心功能

### 1. 规则表现分析

分析回测日志，对比每个规则的：
- **理论准确率**：规则定义时的准确率
- **实际准确率**：回测中的真实表现
- **样本数量**：规则被触发的次数

**输出**：
- 优质规则列表（表现良好，建议保留）
- 表现不佳规则列表（建议淘汰或调整）
- 需要更多样本的规则（样本数不足，需继续观察）

### 2. 新规则挖掘

从数据库历史数据中自动挖掘新的规则模式：
- 分析已完成比赛的赔率特征组合
- 测试不同特征组合的预测准确率
- 筛选出高准确率（≥85%）的规则模式

**挖掘的特征组合**：
- 即时让方 + 即时受让方 + 平赔变化
- 力量差 + 即时让方/受让方
- 即时让方 + 让方赔率变化
- 初盘即时盘一致性

### 3. 规则优化报告

生成详细的优化报告，包括：
- 规则表现排名
- 优质规则推荐
- 低效规则警告
- 新规则建议

## 使用方法

### 基本命令

```bash
# 1. 分析规则表现（分析最近30天的回测数据）
python services/rule_optimizer.py --analyze

# 2. 挖掘新规则（从数据库挖掘优质规则模式）
python services/rule_optimizer.py --mine

# 3. 生成优化报告
python services/rule_optimizer.py --report

# 4. 运行完整优化流程（分析 + 挖掘 + 报告）
python services/rule_optimizer.py --full

# 5. 分析指定天数的数据
python services/rule_optimizer.py --analyze --days 60
```

### 定期自动运行

可以设置定时任务（cron）定期运行优化流程：

```bash
# 每天凌晨2点运行完整优化流程
0 2 * * * cd /home/ubuntu/oddsmind && /usr/bin/python3 services/rule_optimizer.py --full >> /var/log/rule_optimizer.log 2>&1

# 每周一生成周报
0 3 * * 1 cd /home/ubuntu/oddsmind && /usr/bin/python3 services/rule_optimizer.py --report --days 7 >> /var/log/rule_optimizer_weekly.log 2>&1
```

## 规则优化流程

### 1. 数据收集阶段

- `auto_rule_matcher` 服务持续运行，匹配规则并保存到数据库
- 同时保存日志到 `validation_test/logs/monitor/` 目录

### 2. 回测验证阶段

- 比赛结束后，使用 `backtest_log.py` 验证预测结果
- 更新日志中的 `result` 字段

### 3. 规则分析阶段

- 定期运行 `rule_optimizer.py --analyze` 分析规则表现
- 识别优质规则和低效规则

### 4. 规则挖掘阶段

- 运行 `rule_optimizer.py --mine` 从历史数据挖掘新规则
- 发现新的高准确率特征组合

### 5. 规则更新阶段

- 根据分析结果，更新 `auto_rule_matcher.py` 中的规则定义
- 移除低效规则，添加新发现的优质规则
- 重启 `auto_rule_matcher` 服务

## 最佳实践

### 1. 规则评估标准

- **优质规则**：实际准确率 ≥ 理论准确率 - 5%，且样本数 ≥ 5
- **低效规则**：实际准确率 < 理论准确率 - 15%，且样本数 ≥ 5
- **待观察规则**：样本数 < 5，需要继续收集数据

### 2. 规则更新频率

- **每周分析**：每周运行一次完整优化流程
- **每月更新**：根据分析结果更新规则库
- **季度审查**：全面审查规则库，淘汰长期低效规则

### 3. 新规则验证

- 新挖掘的规则需要先在测试环境验证
- 建议样本数 ≥ 10，准确率 ≥ 85% 才考虑加入规则库
- 新规则加入后，持续监控其表现

## 注意事项

1. **数据质量**：确保数据库中有足够的已完成比赛数据
2. **样本数量**：样本数太少的规则可能不够可靠
3. **时间窗口**：使用最近180天的数据挖掘新规则，避免规则过时
4. **规则冲突**：新规则可能与现有规则冲突，需要人工审查

## 故障排查

### 问题：没有找到回测记录

**原因**：日志目录为空或路径不正确

**解决**：
- 检查 `validation_test/logs/monitor/` 目录是否存在
- 确认 `auto_rule_matcher` 服务正常运行并保存日志

### 问题：挖掘不到新规则

**原因**：数据库中没有足够的已完成比赛数据

**解决**：
- 检查 `matches` 表中是否有足够多的 `finished` 状态比赛
- 检查 `odds_analysis_results` 表中是否有对应的分析数据
- 调整 `min_samples` 参数降低样本数要求

### 问题：报告文件未生成

**原因**：报告目录权限问题

**解决**：
- 检查 `validation_test/reports/rule_optimization/` 目录权限
- 确保有写入权限
