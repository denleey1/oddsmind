# 自动备份系统使用说明

## 📋 功能概述

自动备份系统支持：
- ✅ **数据库备份**：自动备份MySQL数据库
- ✅ **应用文件备份**：备份重要的应用配置和代码文件
- ✅ **自动压缩**：备份文件自动压缩节省空间
- ✅ **自动清理**：自动删除过期的旧备份
- ✅ **多种传输方式**：支持本地、远程服务器、S3等多种传输方式
- ✅ **定时执行**：通过cron每天凌晨4点自动执行

## 🚀 快速开始

### 1. 设置定时备份任务

运行设置脚本（会自动配置每天凌晨4点执行）：

```bash
cd /home/ubuntu/oddsmind
chmod +x scripts/setup_backup_cron.sh
./scripts/setup_backup_cron.sh
```

### 2. 配置备份选项（可选）

编辑配置文件 `scripts/backup_config.json`：

```json
{
  "backup_dir": "backups",
  "backup_database": true,
  "backup_app_files": true,
  "compress_backup": true,
  "keep_days": 30,
  "transfer": {
    "enabled": false,
    "type": "local",
    "destination": "/backup/oddsmind"
  }
}
```

### 3. 手动执行备份（测试）

```bash
cd /home/ubuntu/oddsmind
python3 scripts/auto_backup.py
```

## ⚙️ 配置说明

### 基本配置

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `backup_dir` | 备份文件存储目录 | `backups` |
| `backup_database` | 是否备份数据库 | `true` |
| `backup_app_files` | 是否备份应用文件 | `true` |
| `compress_backup` | 是否压缩备份文件 | `true` |
| `keep_days` | 保留备份的天数 | `30` |

### 应用文件备份配置

`app_files_to_backup`: 要备份的文件/目录列表
- `config` - 配置文件
- `core` - 核心模块
- `application` - 应用代码
- `database` - 数据库模块
- `oddsmind.env` - 环境变量配置
- `requirements.txt` - 依赖列表

`app_files_to_exclude`: 排除的文件/目录模式
- `__pycache__` - Python缓存
- `*.pyc`, `*.pyo` - 编译文件
- `.git` - Git目录
- `venv` - 虚拟环境
- `logs` - 日志文件
- `backups` - 备份目录

### 传输配置

#### 1. 本地目录传输

```json
{
  "transfer": {
    "enabled": true,
    "type": "local",
    "destination": "/backup/oddsmind"
  }
}
```

#### 2. 远程服务器传输（使用rsync/scp）

```json
{
  "transfer": {
    "enabled": true,
    "type": "remote",
    "destination": "user@remote-server:/backup/oddsmind"
  }
}
```

**注意**：需要配置SSH密钥认证，避免每次输入密码：

```bash
# 生成SSH密钥（如果还没有）
ssh-keygen -t rsa -b 4096

# 复制公钥到远程服务器
ssh-copy-id user@remote-server
```

#### 3. Amazon S3传输

```json
{
  "transfer": {
    "enabled": true,
    "type": "s3",
    "destination": "s3://my-backup-bucket/oddsmind",
    "aws_access_key_id": "your-access-key",
    "aws_secret_access_key": "your-secret-key",
    "aws_region": "us-east-1"
  }
}
```

**安装依赖**：
```bash
pip install boto3
```

**或使用环境变量**：
```bash
export AWS_ACCESS_KEY_ID=your-access-key
export AWS_SECRET_ACCESS_KEY=your-secret-key
export AWS_DEFAULT_REGION=us-east-1
```

## 📝 使用示例

### 仅备份数据库

```bash
python3 scripts/auto_backup.py --database-only
```

### 仅备份应用文件

```bash
python3 scripts/auto_backup.py --app-only
```

### 使用自定义配置文件

```bash
python3 scripts/auto_backup.py --config /path/to/custom_config.json
```

## 🗑️ 管理定时任务

### 查看当前cron任务

```bash
crontab -l
```

### 编辑cron任务

```bash
crontab -e
```

### 删除备份定时任务

```bash
crontab -l | grep -v 'auto_backup.py' | crontab -
```

### 修改执行时间

编辑cron任务，修改时间表达式：

```bash
crontab -e
```

Cron时间格式：`分钟 小时 日 月 星期`

示例：
- `0 4 * * *` - 每天凌晨4点
- `0 2 * * *` - 每天凌晨2点
- `0 4 * * 0` - 每周日凌晨4点
- `0 4 1 * *` - 每月1号凌晨4点

## 📦 备份文件说明

### 数据库备份

- 文件名格式：`database_YYYYMMDD_HHMMSS.sql` 或 `database_YYYYMMDD_HHMMSS.sql.gz`（压缩后）
- 包含：完整的数据库结构和数据
- 恢复方法：
  ```bash
  # 解压（如果压缩了）
  gunzip database_20240101_040000.sql.gz
  
  # 恢复数据库
  mysql -u root -p oddsmind < database_20240101_040000.sql
  ```

### 应用文件备份

- 文件名格式：`app_files_YYYYMMDD_HHMMSS.tar.gz`
- 包含：配置文件和重要代码文件
- 解压方法：
  ```bash
  tar -xzf app_files_20240101_040000.tar.gz
  ```

## 🔧 故障排查

### 问题1：mysqldump命令未找到

**解决方案**：
```bash
# Ubuntu/Debian
sudo apt-get install mysql-client

# CentOS/RHEL
sudo yum install mysql
```

### 问题2：数据库备份失败

**检查**：
1. MySQL服务是否运行：`systemctl status mysql`
2. 数据库用户权限：确保用户有备份权限
3. 数据库配置是否正确：检查 `oddsmind.env` 中的MySQL配置

### 问题3：传输到远程服务器失败

**检查**：
1. SSH连接是否正常：`ssh user@remote-server`
2. 远程目录是否存在且有写权限
3. SSH密钥是否配置正确

### 问题4：S3传输失败

**检查**：
1. boto3是否安装：`pip list | grep boto3`
2. AWS凭证是否正确
3. S3 bucket是否存在且有写权限
4. 网络连接是否正常

## 📊 备份文件管理

### 查看备份文件

```bash
ls -lh backups/
```

### 手动清理旧备份

```bash
# 删除30天前的备份
find backups/ -name "*.sql*" -mtime +30 -delete
find backups/ -name "*.tar.gz" -mtime +30 -delete
```

### 检查备份文件大小

```bash
du -sh backups/
```

## 🔐 安全建议

1. **备份文件权限**：确保备份文件只有授权用户可访问
   ```bash
   chmod 600 backups/*.sql*
   chmod 600 backups/*.tar.gz
   ```

2. **传输加密**：使用SSH传输时，数据会自动加密

3. **S3加密**：在S3 bucket上启用加密

4. **定期验证**：定期测试备份文件的恢复功能

## 📞 支持

如有问题，请检查：
1. 备份日志：`backups/logs/backup_cron.log`
2. 系统日志：`/var/log/syslog` 或 `journalctl -u cron`
3. 配置文件：`scripts/backup_config.json`
